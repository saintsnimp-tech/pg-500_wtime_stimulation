# 澳洲学生签证等待时长数据

数据快照日期：2026-09-24（Asia/Shanghai）

本目录汇总澳大利亚学生签证（Student visa, subclass 500）等待/处理时长的公开数据。不同来源的统计对象和口径不可直接混用，因此按来源类型拆分。

## 关键口径

- “50% processed in X”是近期已作决定申请的第 50 分位（中位数），不是剩余等待时间预测。
- “90% processed in X”是第 90 分位，不是承诺期限。
- 官网当前指南覆盖最近已决定申请，数值会随处理旧案、申请量、材料完整性及完整性审查而变化。
- 半年报中的处理时长只统计已获批的学生签证主申请（student PRIMARY visa applications granted）；拒签、撤回和仍在等待的申请不在这些分位中。
- 季度“flow rate”是某一批次在同季度或截至快照日已结案的比例，不等同于获签率。
- `0` 和 `<5` 按原表保留：`0`通常表示少于 1 个完整日；`<5`表示隐私/小样本抑制，不能当作精确的 0 或 4。
- 月份不统一换算为天。若平台直接提供天数则保留；否则同时保留原始字符串，避免用固定 30 天造成伪精确。
- 社区个案是自报数据，存在选择偏差、重复、日期错误和类别缺失；分析总体趋势时应默认排除。
- `11` 不保留源站记录 ID、账号、签证官编号及自由文本；专业和学校只保留宽泛分组。`event_observed=0` 的记录是截至 `as_of_date` 仍在等待的右删失样本。
- `duplicate_key` 只表示时间线与宽泛特征相同的疑似重复组，不能证明是同一申请；基线分析折叠，审计表保留。
- `13` 不保存帖子原文、账号、用户名或头像，只保存来源 URL、日期、宽泛类别、内容哈希及解析置信度；`requires_manual_review=yes` 的行不得直接训练。
- `14` 的唯一粒度是 `source_snapshot_date × activity_month × activity_type`。`lodged - granted` 只是两个流量之差；还缺少拒签、撤回、复审、类别变化等状态转移，不能称为 backlog 或“仍在等待人数”。

## 不可混用的数据层

| 层 | 代表文件 | 能回答 | 不能回答 |
|---|---|---|---|
| 官方处理时长 | `01`–`05` | 已决定/已获批申请的历史分位 | 某个个案何时一定出结果 |
| 官方月度流量 | `14`、`15`、`snapshots/` | 特定口径每月递交与批准量及后续修订 | 当前在审库存、真实积压、个案等待天数 |
| 众包个案 | `11`、`12` | 自报时间线的删失生存分析 | 代表所有中国大陆申请人 |
| 社媒/问卷证据 | `08`、`13` | 补充个案与待核验信号 | 直接替代官方总量或无偏总体样本 |

## 建议使用顺序

1. 当前一般预期：先用 `01_official_current_streams_2026-09.csv`。
2. 中国申请人历史变化：用 `04_official_china_quarterly_2024Q4-2025Q4.csv`。
3. 教育类别与境内/境外差异：用 `03_official_sector_quarterly_2024Q4-2025Q4.csv`。
4. 长期压力与结案速度：用 `02_official_aggregate_quarterly_2022-2025.csv`。
5. 第三方和社区信号：只作为补充交叉验证；个案建模读取 `11`，同时应用质量分、右删失和疑似重复折叠。
6. 流量背景特征：读取 `14`，只使用递签月之前的滞后值；因个案表没有国籍，该特征只对 PGR/境外记录充当上下文代理。

## 覆盖边界

“所有平台”不存在可稳定穷尽的公开集合。小红书、微博、X 和微信群只在有官方 API、合规公开 URL、用户授权导出或明确同意时接入；不绕过登录、验证码、反爬或隐私设置。需要登录的 ImmiAccount 个案状态及不可公开复核的帖子未纳入。目录覆盖了截至快照日可公开访问、可引用且与 subclass 500 等待时长直接相关的主要官方数据集、官方报告、FOI 数据、主流处理时长工具和匿名化众包案例。
